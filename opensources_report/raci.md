# 오픈소스 관리 RACI

문서 ID: OSS-RACI-001 · 버전: 1.0 · 작성일: 2026-10-14

적용 범위: 본 저장소. 상태: 기존 CODEOWNERS를 바탕으로 작성한 역할표;
본 역할표의 채택은 문서 변경 PR에서 검토한다.

## 역할 정의

| 역할 | 해당 주체 | 근거 |
| --- | --- | --- |
| 변경 담당자 | 해당 OSS 도입·수정·배포·문서 PR의 실제 작성자 또는 PR에 지정된 담당자 | PR 작성자·담당자 기록 |
| 승인 담당자 | 해당 변경 작성자가 아닌, 승인 리뷰를 수행하는 CODEOWNER 1명 | `@junhyeok-motech`, `@gihuncho` 중 해당 PR의 실제 승인자 |
| 협의 담당자 | 다른 CODEOWNER 및 해당 변경으로 영향받는 기능·배포 담당자 | 필요 시 PR에 참여자와 의견 기록 |
| 관련 기여자 | 해당 변경을 적용·운영하는 저장소 기여자 | PR·릴리스·이슈 연결 |

실명·직책을 새로 임명하지 않는다. 기존 담당 리뷰어 지정은
[CODEOWNERS](../.github/CODEOWNERS)와 [PR #10](https://github.com/MotifTechnologies/motif-agent-tracer-v2/pull/10)으로
Git 관리 완료한 근거를 사용한다. 각 업무의 실제 수행자·최종 승인자는 해당 PR에서 식별한다.

R = 수행, A = 최종 책임/승인, C = 협의, I = 결과 공유.
아래 각 행의 A는 해당 건의 승인 담당자 한 명이다. 조직 전체 정책의 결재권자를 뜻하지 않는다.

## 업무별 책임표

| 업무 | 변경 담당자 | 승인 담당자 | 협의 담당자 | 관련 기여자 | 완료 증빙 |
| --- | --- | --- | --- | --- | --- |
| OSS 후보 선정·평가·제외 등록 | R | A | C | I | 선정 근거와 점수표가 연결된 PR |
| 라이선스 원문·조건·개별 예외 검토 | R | A | C | I | 검토 문서·정확한 버전/해시·승인 리뷰 |
| 허용·제외 정책 변경 | R | A | C | I | 정책 코드·문서·테스트 diff 및 승인 PR |
| 의존성·lock·SBOM 갱신 | R | A | C | I | 변경 커밋, SBOM, licenses 결과 |
| 취약점 영향 확인·수정 | R | A | C | I | 수정 PR, 영향 버전, 재스캔 결과 |
| 취약점 예외 수용·재검토·해제 | R | A | C | I | 예외 목록 diff, 사유·재검토 조건, 승인 PR |
| 배포 고지·라이선스 포함 확인 | R | A | C | I | 배포물 확인 결과, NOTICE/LICENSE 변경 |
| 자산목록 갱신·범위 대조 | R | A | C | I | 자산목록 PR 및 조사 범위 |
| 정기 검사 결과 확인·후속 조치 | R | A | C | I | scheduled run 및 후속 수정 PR |
| 심의 안건 작성·결정 기록 | R | A | C | I | 실제 서면 검토/회의록 및 결정 승인 |
| CI 증빙 만료 전 보존 | R | A | C | I | 보존 위치·대상 커밋·해시·담당자 기록 |

## 운영 방법

1. 업무를 시작할 때 PR 또는 이슈에 변경 담당자와 처리 범위를 기록한다.
2. 승인 담당자는 PR 작성자와 구분한다. 승인 리뷰의 실제 계정과 일자를 근거로 남긴다.
3. 자동 CI는 실행 수단이다. CI 성공만으로 사람의 검토·책임 역할이 수행된 것으로 기록하지 않는다.
4. 담당 변경은 이 표 또는 CODEOWNERS의 PR에서 검토한다. 인수인계할 미해결 건도 연결한다.
5. 조직 차원의 법무·보안·자산 책임자가 필요한 건은 실제 지정이 확인된 후 기록한다. 미지정 인물을 임의로 담당자로 기재하지 않는다.

## 검수

- [ ] 기존 CODEOWNERS와 승인 담당자 정의가 일치한다.
- [ ] 실제 변경 담당자·승인 담당자를 PR에서 확인할 수 있다.
- [ ] 필요한 협의 담당자가 누락되지 않았다.
- [ ] 증빙 보존 업무의 실제 담당자와 보존 위치를 해당 건에 지정했다.
